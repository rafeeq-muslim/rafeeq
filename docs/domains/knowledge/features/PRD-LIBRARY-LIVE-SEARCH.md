## 1. الهدف والنطاق

**الإصدار المصحح: مصادر بحث المكتبة هي الموسوعة وإسلام هاوس فقط. هذه قائمة مستقلة عن مصادر الشات؛ لا تستخدم قائمة الشات الافتراضية ولا تغيرها.**

إضافة محرك بحث أعلى شاشة المكتبة الظاهرة في الصورة، يبحث مباشرة في موسوعة المحتوى الإسلامي وإسلام هاوس فقط، ويعرض مواد وروابط يمكن فتحها. تحتفظ المكتبة بأقسامها وكتبها الحالية قبل بدء البحث وبعد مسحه.

هذه واجهة اكتشاف محتوى: تعرض عنوان المادة ونبذة مقتبسة من المصدر ورابطها، ولا تنشئ إجابة دينية بالذكاء الاصطناعي. يجوز عرض نتيجة من مصدر واحد؛ لا عدد إلزامي ولا ترتيب مواقع مفروض، ولا يلزم أن يظهر كل مصدر في كل بحث.

داخل النطاق: حقل البحث، عرض النتائج، فلاتر المصدر والنوع المتاح، اللغة، تحميل المزيد، حالات التحميل والفشل الجزئي، ربط الموصلات من الخادم. خارج الإصدار الأول: توليد ملخصات بالذكاء الاصطناعي، حسابات وتخصيص حسب تاريخ المستخدم، استيراد نتائج البحث تلقائيًا ككتب معتمدة، وحفظ نتائج خارجية جديدة قبل تصميم توافقها مع نظام الحفظ.

## 2. ما هو موجود وما يحتاج إضافة

النسخة السابقة من الأرشيف تحتوي:

- `frontend/src/app/discover/Library.tsx` لواجهة المكتبة.
- `frontend/src/app/discover/queries.ts` و`types.ts` لدعم البيانات.
- `backend/app/knowledge/discover.py` وفيه `GET /api/discover/library` الذي يعرض مواد منشورة/معتمدة بحسب اللغة، مع إخفاء الروابط المعطلة.
- `backend/app/knowledge/library.py` لتحميل مواد المكتبة ومراجعة الروابط.

هذا المسار القائم يعرض مكتبة منتقاة؛ لا يثبت وجود بحث حي. يجب فحص checkout الحالي لأن المستخدم طبّق تعديلات بعد الأرشيف. نضيف مسار بحث مستقلًا، ونبقي القائمة المعتمدة الحالية كما هي. نتيجة بحث خارجية لا تحمل تلقائيًا وصف «مراجعة من فريق رفيق»؛ تعرض بوصفها مادة من المصدر المحدد.

## 3. تجربة المستخدم

### الحالة قبل البحث

أسفل عنوان «المكتبة» وقبل أقسام الكتب:

- حقل ذو label واضح «ابحث في المصادر» وplaceholder «ابحث عن موضوع أو سؤال…».
- زر «بحث» يدعم Enter، وزر مسح يظهر عند وجود نص.
- سطر تعريفي مختصر: «ابحث في موسوعة المحتوى الإسلامي وإسلام هاوس».
- أقسام المكتبة الحالية تبقى ظاهرة عندما لا يوجد بحث مرسل.

إرسال البحث صريح بالزر أو Enter؛ لا نرسل كل ضغطة مفتاح إلى مصادر خارجية. لا يُرسل أثناء IME composition. النص من 2 إلى 200 حرف بعد trim، مع رسالة طول واضحة. تبقى المسودة إذا فشل الطلب.

### حالة النتائج

بعد الإرسال تظهر النتائج بدل أقسام التصفح في مساحة المحتوى نفسها، مع زر واضح «العودة إلى المكتبة» أو مسح البحث.

بطاقة النتيجة:

1. عنوان المادة كما ورد في المصدر.
2. اسم المصدر وشارة النوع إذا أمكن إثباته: سؤال وجواب، مقال، كتاب، حديث، مادة قرآنية…
3. نبذة نصية قصيرة من المصدر، لا ملخص مولد؛ يمكن حذفها إذا لم يوفر الموصل نصًا مناسبًا.
4. زر «فتح في المصدر» مع إشارة رابط خارجي. لا تشغيل صوت أو تحميل ملف تلقائيًا.
5. اللغة عند اختلافها عن واجهة التطبيق، لكن الوضع الافتراضي يقصر البحث على لغة المستخدم المدعومة.

يعرض العداد «النتائج المعروضة: 12» بدل ادعاء عدد شامل لا توفره المصادر. لا يعرض زمن نشر مختلقًا؛ وقت الجلب ليس تاريخ نشر المادة.

### الفلاتر

- المصدر: «الكل»، «موسوعة المحتوى الإسلامي»، «إسلام هاوس».
- نوع المادة: يظهر فقط إذا وفرت الموصلات تصنيفًا موثوقًا؛ لا تُصنف مادة عشوائيًا ككتاب.
- تغيير المصدر يرسل البحث إلى المصادر المختارة فقط. نتيجة صفر من مصدر مختار لا تؤدي خفية إلى البحث في «الكل».
- عرض RTL صحيح، وتركيز لوحة المفاتيح وlabels وحالة التحميل عبر aria-live دون تكرار مزعج.

## 4. خصوصية البحث واتساق نص الشاشة

تقول الشاشة الحالية «لا نسجل ما تفتحه، ولا يراه أحد غيرك». عند إضافة بحث خارجي يجب أن تظل الرسالة دقيقة:

- لا يُضاف تسجيل دائم لعبارات البحث أو سجل فتح للمستخدم لهذا الإصدار.
- تستخدم API بنمط POST كي لا توضع عبارة السؤال في query string الذي قد يدخل سجلات URL، مع تعطيل تسجيل body لهذا المسار في الخادم والوكيل وأدوات الرصد.
- لا تحفظ عبارة البحث في localStorage أو analytics أو عنوان URL افتراضيًا. تُحتفظ في ذاكرة الجلسة اللازمة للعرض فقط.
- يضاف توضيح موجز بجوار البحث: «يُرسل نص البحث إلى المصادر لجلب النتائج». لا تُرسل هوية المستخدم أو المحادثة السابقة.
- يصحح نص المكتبة إلى عبارة محددة مثل «لا نحفظ سجل فتح المواد في رفيق»، بشرط مطابقة ذلك للتنفيذ الحالي بعد مراجعته. لا يُعد المستخدم بأن المواقع الخارجية لا ترى البحث أو الزيارة.
- الروابط الخارجية تستخدم سياسة مناسبة لمنع إرسال referrer، مع `noopener noreferrer` عند الفتح في تبويب جديد، وعنوان URL من نطاق موثوق.

## 5. الربط المباشر بالمصادر

إعادة استخدام adapters الحية المنفذة للشات إن وجدت، بدل بناء تكامل منفصل متناقض. واجهة المكتبة تستعمل search وmetadata؛ لا تحتاج سلسلة مؤلف ومدقق إجابة كاملة لأنها لا تولد أجوبة.

لكل موصل يثبت المطور: الاسم الفعلي، الإصدار، الأدوات/العمليات المتاحة، اللغات، البحث والترقيم الصفحي، وروابط النتائج الأصلية. تُختبر الأدوات من backend المنشور، لا من Claude وحده. لا تُخترع endpoints أو أسماء MCP tools.

موصل «موسوعة المحتوى الإسلامي» يحدد من إعداد المشروع؛ لا يُستبدل تلقائيًا بـ`islamhouse_enc` دون إثبات أنه المقصود. إذا غاب موصل مطلوب، تُنفذ الأعمال المستقلة ويُذكر النقص بوضوح؛ لا يُعلن اكتمال المصدرين.

عند اختيار «الكل»، يبدأ البحث في الموصلين المفعّلين والداعمين للغة بالتوازي. فشل أحدها لا يسقط نتائج الآخر. فحص اللغة لا يتحول إلى ترجمة شرعية آلية. يبقى الاسم الحقيقي للموقع في النتيجة ولو أعادت الموسوعة مادة أصلها موقع آخر، مع حفظ provenance إن توفر.

إسلام هاوس هو المصدر المطلوب بمعرّف مقترح `islamhouse`، ويُثبت ربطه بخدماته الفعلية. ليس مجرد إعادة تسمية لموصل موقع آخر، ولا يفترض أن `islamhouse_enc` المحلي يغطي مكتبة إسلام هاوس أو يتيح البحث الحي. إذا كان موصل واحد يتيح الموسوعة وإسلام هاوس، يميز التطبيق عمليات البحث وهوية النتائج والفلاتر، ويزيل تكرار المواد المشتركة.

## 6. عقد API المقترح

مسار جديد: `POST /api/discover/library/search`، بجوار endpoint التصفح الحالي. الضيف يستطيع البحث وفق حدود الاستخدام القائمة.

```json
{
  "query": "فضل الوضوء",
  "lang": "ar",
  "sources": ["islamic_content", "islamhouse"],
  "type": null,
  "page_size": 12,
  "cursor": null
}
```

```json
{
  "search_id": "opaque-id",
  "status": "partial",
  "items": [
    {
      "id": "stable-source-record-id",
      "source_id": "islamhouse",
      "title": "عنوان المادة من المصدر",
      "snippet": "مقتطف متاح من المصدر",
      "type": "book",
      "lang": "ar",
      "url": "https://islamhouse.com/...",
      "retrieved_at": "ISO-8601"
    }
  ],
  "source_status": [
    {"source_id": "islamhouse", "status": "ok"},
    {"source_id": "islamic_content", "status": "timeout"}
  ],
  "next_cursor": null
}
```

المثال شكل عقد فقط، وليس نتيجة حية أو رابط مادة حقيقية. في التنفيذ تأتي الروابط من نتائج موصل مثبت.

- `sources` محصورة في قائمة المكتبة: `islamic_content` و`islamhouse` فقط؛ أي مصدر آخر يرفض بـ422، حتى لو كان مسموحًا للشات. لا fallback خفي لمواقع أخرى. حذف الحقل يعني الكل؛ قائمة فارغة مرفوضة بـ422 ولا تعني الكل ضمنيًا.
- `page_size` بين 1 و20، الافتراضي 12. قيم type واللغة تحقق كتعداد معروف.
- `status`: success أو partial. انعدام النتائج مع نجاح البحث ليس عطلًا. فشل كل المصادر يرجع خطأ خدمة منظمًا مناسبًا، و429 لحد الاستخدام و422 للمدخل غير الصحيح.
- لا تُرسل أسرار أو raw provider errors للعميل. يمكن للواجهة عرض المصادر التي تعذرت بأسمائها فقط.
- نتائج هذا endpoint لها `Cache-Control: no-store`، ولا تنسخ إعداد PUBLIC من endpoint التصفح الحالي تلقائيًا.

## 7. الدمج والترتيب وتحميل المزيد

تطبيع Unicode والمسافات والتشكيل في نسخة البحث بما يتوافق مع PRD الأول، مع الحفاظ على النص الأصلي، وعدم تغيير النفي أو المعنى. يُرسل الاستعلام الآمن إلى الموصلات، وتُحول النتائج لعقد موحد.

تُزال المكررات باستخدام هوية السجل والرابط الأصلي الموحّد. لا يحذف مصدر مختلف لمجرد تشابه عنوانه؛ ويُجمع تكرار الرابط نفسه القادم من عدة أدوات، مع الاحتفاظ بأصل النتيجة.

الترتيب بحسب الصلة: ترتيب المصدر الداخلي ثم دمج مضبوط مثل reciprocal-rank fusion عندما تكون rankings متاحة. لا تُقارن درجات مزودين بمقاييس مختلفة كأنها مقياس واحد. يستخدم معرف ثابت لكسر التعادل. لا نسب متساوية إلزامية للمواقع، ولا انحياز صامت يجعل مصدرًا لا يصل إلى النتائج رغم وجود نتائج مناسبة.

«تحميل المزيد» يستخدم cursor معتمًا مضبوطًا على الاستعلام/اللغة/الفلاتر، لا offset عالميًا اعتباطيًا عبر مواقع متعددة. التصميم المقترح جلسة بحث قصيرة العمر في الذاكرة/مخزن مؤقت مشترك متاح بالمشروع، تحفظ النتائج المجلوبة وcursors والـseen IDs، وتنتهي خلال 5 دقائق. لا يتحول هذا إلى سجل بحث دائم. تغيير الفلاتر يبدأ جلسة جديدة. عند انتهاء الجلسة تظهر «انتهت جلسة البحث، أعد البحث».

إذا اختير cursor عديم الحالة بدل الجلسة، يجب ألا يكشف نص السؤال أو رموز المزود وأن يُحمى من العبث، وأن يمنع إعادة استخدامه مع استعلام آخر. عند غياب pagination في مصدر، يسجل انتهاؤه ولا يعيد الصفحة الأولى إلى الأبد. لا يُدعى توفر مزيد من النتائج إذا لم يعرف النظام ذلك.

## 8. المهل والأمن وحالات الواجهة

- مهلة خلفية كلية مقترحة 12 ثانية، ومهلة واجهة 15 ثانية. تُحجز نافذة متوازية للمصادر ضمن الإجمالي؛ لا تجمع مهلاتها بالتتابع.
- حد 4 نداءات لكل مصدر لكل صفحة وسقف مشترك 8، مع إعادة واحدة فقط للفشل المؤقت داخل الوقت. يمكن تخفيض الحدود وفق مخطط الموصل الحقيقي.
- عند اكتمال النافذة تعاد النتائج المتاحة مع partial وتلغى المهام المعلقة. لا تبقى مؤشرات انتظار دائمة.
- لكل إرسال request ID؛ رد البحث القديم لا يستبدل بحثًا أحدث. AbortController وإلغاء المهام الخلفية حسب الإمكان، مع حد الاستخدام دون اعتماد على إلغاء المتصفح فقط.
- يحافظ search الجديد على نمط rate limiting بالمشروع. قياسات logs: المصدر، الحالة، الزمن وعدد النتائج فقط دون query أو بيانات شخصية.
- تُعرض النصوص كنص آمن؛ لا يُحقن HTML المزود في DOM. تراجع الروابط والتحويلات وتمنع العناوين الداخلية/الخاصة وروابط التنفيذ.

| الحالة | العرض |
| --- | --- |
| تحميل | «جارٍ البحث في المصادر…» مع واجهة قابلة للمسح/الإلغاء |
| نتائج | بطاقات المصدر والنوع والرابط |
| partial مع نتائج | النتائج + «تعذر البحث في بعض المصادر» دون إخفاء الناجح |
| صفر نتائج وكل البحث سليم | «لم نجد نتائج مناسبة. جرّب كلمات أخرى.» |
| صفر نتائج مع تعطل بعض المصادر | «لم تظهر نتائج من المصادر المتاحة، وتعذر البحث في بعضها.» |
| فشل الجميع | رسالة اتصال وإعادة محاولة؛ لا ادعاء عدم وجود محتوى |
| offline | الكتب الحالية المتاحة بحسب سلوك التطبيق + تنبيه أن البحث المباشر يحتاج اتصالًا |
| لغة غير مدعومة | بيان المصدر غير المتاح بهذه اللغة؛ الاستمرار بالباقي |

## 9. التنفيذ بالترتيب وخريطة الملفات

1. فحص `Library.tsx` وqueries/types وdiscover.py الحاليين، وتوثيق سلوك التصفح والمراجعة والحفظ قبل التعديل.
2. إثبات موصلات البحث الحية من backend وتحديد الموسوعة الفعلية.
3. إنشاء وحدة بحث مكتبة مثل `backend/app/knowledge/library_search.py`: توحيد نتائج، تزامن، عزل أعطال، pagination وفلاتر.
4. إضافة route منفصل في `backend/app/knowledge/discover.py` وعقد مدخل/مخرج واختبارات. إبقاء endpoint القائمة المعتمدة دون تغيير غير لازم.
5. ربط الموصلات المشتركة في `backend/app/knowledge/live_sources/` إن كانت موجودة، وإضافة metadata adapters فقط عند الحاجة. لا تشغيل مؤلف جواب لتوليد snippets.
6. إضافة `LibrarySearch.tsx` بجوار `frontend/src/app/discover/Library.tsx` وربطه بالصفحة، وتوسيع `queries.ts` و`types.ts`، وواجهة بطاقات مناسبة للنمط الحالي.
7. تحديث `frontend/src/app/i18n/ar.ts` وen.ts وtl.ts، وتصحيح رسالة الخصوصية بناء على السلوك الفعلي.
8. ضبط المهل ومحدد الاستخدام والـno-store ومنع تسجيل النص في البنية الخلفية/الوكيل. مراجعة أدوات analytics الفعلية.
9. اختبار بالموصلات المحاكية ثم عينة حية محدودة، على الهاتف ولوحة المفاتيح، ثم إطلاق تدريجي.

المسارات الجديدة مقترحة. لا تُضاف خدمة تخزين خارجية لمجرد مثال pagination إذا أمكن استخدام البنية الموجودة بأمان. لا migration لكتب المكتبة مطلوبة افتراضيًا، ولا تدمج المواد الخارجية في قائمة منشورة دون مسار مراجعتها.

| ID | الاختبار | المطلوب |

| B11 | cursor منتهي أو لفلاتر مختلفة | رفض منظم وبدء بحث جديد |
| B12 | HTML/URL غير مسموح | نص آمن وروابط معتمدة دون XSS/SSRF |
| B13 | لغة/نوع غير مدعوم | لا بيانات مصنفة أو مترجمة اعتباطيًا |
| B14 | خصوصية | لا نص query في logs/URL/analytics/localStorage؛ توضيح الإرسال الخارجي |
| B15 | نتيجة خارجية | اسم ورابط حقيقيان دون ادعاء مراجعة فريق رفيق |
| B16 | هاتف وRTL ولوحة مفاتيح | لا قص للمحتوى، labels وتركيز وحالة تحميل واضحة |
| B17 | offline/timeout/429/422 | نهاية مفهومة للطلب دون تعليق |
| B18 | موصل داخل Claude فقط | لا يمر اختبار التكامل الخلفي |
| B19 | مراجعة المكتبة القائمة | المواد غير المنشورة والروابط المخفية لا تعود عبر endpoint القائمة |
| B20 | منع التداخل مع الشات | بحث المكتبة لا يضيف قيود مصادر أو رسائل جديدة لمسار السؤال |
| B21 | طلب مصدر خارج قائمة المكتبة | رفض 422، وعدم البحث خارج الموسوعة وإسلام هاوس |
| B22 | إسلام هاوس والموسوعة عبر موصل مشترك أو بيانات متداخلة | فلاتر وهوية نتائج صحيحة وإزالة المكرر؛ لا اعتبار اتصال أحدهما إثباتًا للآخر |

مؤشرات الإطلاق: نجاح اختبارات العقد والخصوصية والانحدار، اختبار search حي لكل مصدر من backend، عينة استعلامات عامة مناسبة لكل مصدر، وزمن P95 مستهدف ≤8 ثوانٍ تحت الخدمات السليمة مع نهاية الطلب ضمن المهلة. لا وعد بأن كل عبارة ستعطي نتيجة من كل موقع.
